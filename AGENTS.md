# Agent guidance

## Generated assets
- The root readme.md is generated by cmd/bootstrap/main.go. **Do not hand-edit readme.md**; modify its generator or its source data and regenerate when documentation genuinely needs to change.
- Treat generated images and other committed outputs as artifacts with an identifiable source and reproducible generation path. Never rewrite unrelated generated assets while verifying one pattern.

## image.Image behaviour and tests
- Preserve standard Go image.Image behaviour, including Bounds and At coordinates, clipping, palette/alpha semantics and determinism for explicitly fixed inputs. Verify the actual contracts of an individual pattern before imposing restrictions on all patterns.
- Unit tests should use small in-memory images, explicit pixel/bounds assertions and named cases where practical; reserve image files or goldens for behaviour that truly needs whole-image comparisons.
- When randomness or time is involved, inject or fix the seed/source in tests rather than depending on ambient process state.
- Preserve compatibility of existing constructors and composable pattern operations. Use narrow, standard interfaces instead of generic mock frameworks.

## Agent follow-through
Review generators, representative pattern implementations and tests, then report any real missing contracts in issue #194. Keep source changes in separate scoped PRs with reproducible generation evidence.
